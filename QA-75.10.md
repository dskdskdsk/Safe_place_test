# 75.10 — Status presentation

Automated checks: status7510 (details ownership, timeline adjacency/gaps, named filters, Notes search and calendar drawer); status759 (archive/restore and persistence failures); status758 (import conflicts, repetition, rollback, taps); status755 (calendar/dashboard/memories); regression full_roundtrip and import_rollback; mobile UI checks.

Details use statusNoteStatus as owner. Legacy unowned details are displayed only for travel/other. Existing text is retained; ownership is established when changing status or editing details. There is one details value per day, not a separate note history for every status. Switching status is persisted atomically.

Timeline segments require consecutive dates, matching status IDs and matching displayed details. Counts still count recorded days. Names in Notes, drawer and timeline filters are escaped; Notes search includes names.

Physical iPhone acceptance: check named filters and long names, search for a custom status, travel details after switching to Home and back, double-tap editing, archive/restore, and backup roundtrip. Automated browser checks do not substitute for Safari device verification.

Known legacy limitation: ownership of old custom-status notes cannot be inferred reliably. Those raw values remain stored but are not displayed without a matching owner. Previously deleted historical statuses cannot be reconstructed by this release.
