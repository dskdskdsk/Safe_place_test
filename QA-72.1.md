## Реалізація та контракт

У повному index.html додано глобальні функції:

```js
readInsightDay(snapshot, dateKey, asOf)
readInsightPeriod(snapshot, from, to, asOf)
```

Усі дати — явні рядки `YYYY-MM-DD`. Невалідна дата або перевернутий період
дає TypeError. Період обрізаний до asOf включно; повністю майбутній період
повертає нуль днів, null-метрики та null-частки без знаменника. Окремий читач
дня дозволяє прочитати збережений майбутній день з `isFuture: true`; читач
періоду його до підсумків не включає. Календар перебирається за компонентами
дати в UTC-носії без часової зони, без додавання 86400000 мс локального часу.
Це забезпечує однакові календарні ключі на переходах DST.

Читачі не звертаються до day(), ensureSummaryEntries(), save(), persist(),
DOM, storage, Date.now() чи Math.random(). Чинні каталоги BUILT_IN/STATUS_DATA
використовуються лише для ID/категорій; локалізовані getter-підписи не читаються.
Нових днів, ID чи часу в журнал не записують. Виходи складаються з нових
масивів/об'єктів та примітивів; вкладені виходи можна змінювати без зміни входу.

Профіль дня містить:

- `ratings`: count, mean, range, meanAbsoluteDeviation, entries. Валідні лише
  скінченні числові 1–10; валідні dayRatings мають пріоритет над dayRating.
  Рядки не перетворюються на числа. Для n < 2 range і deviation — null.
- `entries`: count/textCount/voiceCount і sources. Голосовий запис потребує
  audioId, текстовий — непорожнього тексту. Придатні summaryEntries мають
  пріоритет над summary; legacy summary — один запис, якщо немає придатних
  entries та _summaryCleared. Чернетка й preview не враховуються.
- `emotions`: uniqueIds, knownLevels як `{id, level}`, unknownIds і sources.
  ID об'єднуються з дня та придатних entries, включно з emotion/emotionId.
  Невідома категорія не знищує ID і не стає neu. Власні рівні — строго
  pos/neu/neg, без запасного значення allEmotions().
- `status`: id/known; невідомий збережений статус зберігає свій ID.
- `habits.markedIds`: наявні truthy-відмітки habitLog за чинним суфіксом дати,
  включно з ID без поточного визначення. day.habits і планова частота не читаються.
- `flags`: наявність кожного каналу та hasSubmittedData. Збережені події, ідеї
  (включно з датованим ideaTree), вдячності та медіа також утворюють
  спостережуваний день. Автоматично порожні days і чисті чернетки — ні.
- `quality`: походження часу оцінок, діагностика невалідних елементів та обмеження.
  Без початкових ts/recordedDay/retro походження unknown; HH:MM його не доводить.
  Для entries час походження лишається unknown, звичайний запис о 00:00 не
  позначається мігрованим. Внутрішні source-посилання стабільні: дата/поле/індекс.

Профіль періоду містить requestedRange, фактичний range, calendarDayCount,
availableHistoryStart, days, counts/coverage, ratings, entries, emotions та
limitations. Coverage має `{count, denominator, fraction}` для оцінок, емоцій,
статусів, записів, звичок і спостережуваних днів. Окремо підраховані записи без
оцінок, оцінки без записів і неспостережувані дні.

Середня й медіана періоду використовують середні оцінених днів з однаковою
вагою. `medianAbsoluteDeviation` — медіана відхилень D від медіани D;
для менш ніж двох днів — null. Сусідні пари мають обидві оцінені календарні
дати: пропуски не перестрибуються. Повертаються число пар і середня абсолютна
різниця. Ритм записів: число записів/днів, text/voice та медіана кількості
серед днів із записами. Частота емоції має окремий знаменник днів з будь-якими
емоціями, кількість і посилання на дати. availableHistoryStart обчислюється
також для habit-only/idea-only дат; це доступна історія, не дата початку користування.

## Походження оцінок і сумісність

Обробник кліку захоплює один Date і активний день. makeRecordedRating отримує
цей самий Date та формує `{v,t,ts,recordedDay,retro}`. TODAY не використовується.
Захист від застарілого обробника не дозволяє записати клік після зміни дня
без відповідного renderRating.

makeEditedRating зберігає початкові поля об'єкта та змінює v, edited і editedAt.
Legacy-число перетворюється на `{v,edited:true,editedAt}` без t/ts. Повторне
редагування оновлює editedAt; старі metadata заднім числом не додаються.
Невалідні metadata не виключають валідне v із середніх: походження unknown,
наявні невалідні поля отримують діагностику. recordedDay не виводиться з ts
після зміни часового поясу. Відсутній retro лишається null у профілі.

Переглянуто всі шляхи перетворення/передачі оцінок:

| Шлях | Поведінка |
|---|---|
| day() | Обгортає старий dayRating у масив; наявні об'єкти не обрізає |
| ratingVal / ratingEntries / calcDayRating | Числове читання/фільтрація для UI, без перезапису metadata |
| syncDayRating | Перераховує тільки сумісний dayRating, масив з metadata зберігає |
| renderRating | Додавання/редагування через нові helpers; видалення — splice |
| markNow / persist / load | Серіалізація всього стану; відкат snapshot включає metadata |
| validateJournal | JSON-клон, структурні перевірки; поля оцінок не обрізає |
| full/period export | Передають повні days з об'єктами оцінок |
| buildCombinedZip | JSON.stringify повного легкого об'єкта; ratings не перетворює |
| safeImportJournal / importJournalJson / mergeJournalJson | Валідація, копія, merge цілих днів, транзакційний persist |
| popup / старі Insights / rollups | Числове відображення/аналіз, початкові оцінки не нормалізують |

## Відомі межі

Реальний iPhone, VoiceOver, системний масштаб, нативний мікрофон та Files
перевіряє автор. Автоматизовані UI-перевірки й screenshots — Chromium,
частина подій popup синтетично відправлена в реальні DOM-обробники.
Це не повний аудит імпорту, PIN-reset, безпеки чи DST всього застосунку:
DST перевірено для нових читачів, інші відкладені питання не закриті.
Реальні особисті архіви не використовувалися. Для старих записів після
давньої міграції неможливо довести справжнє походження часу — воно unknown.

Для PWA слід використовувати повний пакет (index.html, sw.js, manifest.json,
іконки), поданий через HTTP(S); сам HTML надано окремо для перегляду/передачі.
GitHub/Vercel публікуються окремо на пряме доручення автора після локальних перевірок. Фактичний commit та URL див. у відповіді про публікацію.

## Додаткова перевірка порожньої оцінки в HTML-вкладенні

Скриншот автора показував шапку картки без шкали й порожню дату в шапці
сторінки. Той самий стан відтворено на оригінальному 72.1 HTML через HTTP
з java_script_enabled=False: 0 кнопок, дата порожня. З JavaScript: 10 кнопок,
дата заповнена, без pageErrors. Це узгоджується з обмеженнями перегляду
HTML-вкладення; без доступу до iPhone не стверджуємо, що його WebView
безпосередньо продіагностовано. file:// у цьому середовищі заблоковано політикою,
тому локальний file:// та iOS Quick Look тут не перевірялися.

У початковий HTML rating-row додано статичне пояснення UK/EN. renderRating
замінює його кнопками, тому звичайний UI та зберігання незмінні. Цей fallback
видимий також у sandbox, де noscript міг би не допомогти. Додано перевірку
без JS і з JS через HTTP; реальний Vercel Preview перевіряється після deployment.
